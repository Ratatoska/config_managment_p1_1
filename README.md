# Эмулятор командной строки

**Практическая работа № 1 · Вариант 8 · Комаров В.Ю. · ИКБО-41-25**

Графический эмулятор UNIX-подобной оболочки на Python и Tkinter.
Виртуальная файловая система (VFS) загружается из JSON. Каталоги,
содержимое файлов и права хранятся в памяти на время сеанса.

Реализованы все пять этапов задания. Каждый этап сохранён отдельным
коммитом с пояснением изменений и отмечен тегом `stage-1` … `stage-5`.

## Быстрый запуск

Нужен Python 3.10 или новее с модулем Tkinter. Сборка не требуется,
внешние Python-библиотеки не используются.

В Windows запустите **`demo.bat`**: откроется окно, загрузится учебная
VFS и выполнится демонстрационный сценарий. После него можно вводить
свои команды. Для запуска без сценария используйте **`run.bat`**.

Linux или Git Bash:

```bash
bash run.sh
bash run.sh examples/vfs.json examples/startup_demo.txt
```

Прямой запуск из корня проекта:

```bash
python -X utf8 src/main.py
python -X utf8 src/main.py examples/vfs.json examples/startup_demo.txt
```

Имя VFS отображается в заголовке окна. Ввод и результаты остаются
в истории терминала; ошибка команды позволяет продолжить сеанс.

## Параметры запуска

```text
main.py [путь_VFS] [путь_стартового_скрипта] [--headless]
```

| Параметр | Назначение и значение по умолчанию |
| --- | --- |
| `путь_VFS` | JSON-файл VFS. По умолчанию — `examples/vfs.json` внутри проекта. |
| `путь_стартового_скрипта` | Необязательный UTF-8 файл с командами, по одной на строке. |
| `--headless` | Выполнение без окна для автоматических проверок. Без сценария читает команды из стандартного ввода. |

При старте выводятся значения всех параметров. В стартовом сценарии
пропускаются пустые строки и строки, начинающиеся с `#`. Каждая команда
и её результат отображаются; ошибки содержат номер строки и выполнение
продолжается. `exit` останавливает сценарий и закрывает окно.

Пример выполнения без окна:

```bash
python -X utf8 src/main.py examples/vfs.json examples/startup_stage5.txt --headless
```

Скрипты запуска поддерживают переменную `PYTHON` для выбора конкретного
интерпретатора. В Windows проверяется доступность `python`, затем
`py -3`; в Bash выбирается `python3` или `python`.

## Команды варианта 8

| Команда | Поддерживаемое поведение |
| --- | --- |
| `ls [-a] [-l] [-d] [путь]` | Список содержимого каталога или имя файла. `-a` включает скрытые элементы, `.` и `..`; `-l` показывает права, владельца и размер; `-d` показывает сам каталог. Флаги объединяются, например `-lad`. |
| `cd [путь]` | Переход по VFS. Без аргумента — корень; `..` — родитель; `~` — виртуальный корень; `-` — предыдущий каталог. |
| `find [путь] [-name маска] [-type f\|d]` | Рекурсивный поиск по имени и типу. По умолчанию начинает с текущего каталога. Выводит абсолютные пути. |
| `cal [год]` или `cal [месяц год]` | Текущий месяц, весь указанный год или заданный месяц. Неделя начинается с понедельника. Годы: 1–9999. |
| `who` | Имя пользователя реальной ОС и имя компьютера для текущего сеанса эмулятора. |
| `mkdir [-p] путь [путь …]` | Создание одного или нескольких каталогов в памяти. `-p` создаёт родителей и допускает уже существующий каталог. |
| `chmod [-R] режим путь [путь …]` | Изменение прав в памяти. Восьмеричный режим `000`–`777` или символические выражения, например `u=rwx,g=rx,o=` и `a+x`. `-R` включает потомков. |
| `exit` | Завершение сеанса. Аргументы не принимаются. |

Пути с пробелами заключаются в одинарные или двойные кавычки.
`ls`, `mkdir` и `chmod` поддерживают разделитель параметров `--`.

Проверка доступа использует биты владельца, если он совпадает с текущим
пользователем, иначе — биты остальных пользователей. Для перехода
нужно право `x`, для просмотра каталога — `r` и `x`, для создания
каталога — `w` и `x` у родителя. Менять права может владелец узла.
Групповые биты сохраняются и отображаются; членство в группах ОС
в этой учебной модели не определяется.

Символические режимы поддерживают `u`, `g`, `o`, `a`, операции `+`,
`-`, `=` и права `rwx`; без указания класса выбираются все классы.
Специальные биты, копирование прав между классами, символические
ссылки, конвейеры, перенаправления и внешние программы не реализованы.
`who` показывает текущий сеанс эмулятора, а не список всех входов в ОС.

## Пример работы

```text
ls -la
cd "my folder"
cd /
find / -name "*.txt" -type f
cal 10 2026
who
mkdir -p /work/project/results
chmod 700 /work
ls -ld /work
chmod -R u=rwx,g=rx,o= /work
mkdir /work
unknown_command
exit
```

Повторный `mkdir /work` и неизвестная команда демонстрируют ошибки.
Изменения исчезают после завершения сеанса: исходный JSON не меняется
и виртуальные файлы не распаковываются на диск.

## Формат VFS

```json
{
  "name": "my-vfs",
  "entries": [
    {"path": "/", "type": "dir", "mode": "755"},
    {"path": "/docs", "type": "dir", "mode": "755"},
    {
      "path": "/docs/hello.txt",
      "type": "file",
      "mode": "644",
      "content": "SGVsbG8hCg=="
    }
  ]
}
```

`name` задаёт имя системы, `entries` — список узлов. `path` —
нормализованный абсолютный UNIX-путь, `type` — `dir` либо `file`.
Содержимое файла `content` кодируется в base64, включая бинарные данные.
Каталог не содержит данных. Корень `/` обязателен; все родительские
каталоги должны присутствовать, повторяющиеся пути запрещены.

Необязательные поля: `mode` — права (по умолчанию `755` для каталога,
`644` для файла), `owner` — владелец (по умолчанию пользователь ОС).
Ошибки чтения, JSON, структуры и base64 выводятся при запуске.

В `examples` представлены минимальная система, система с несколькими
файлами, система с тремя вложенными каталогами и ошибочный JSON.

## Проверки и сценарии

Из корня проекта:

```bash
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/check_quality.py
```

В Bash можно выполнить `bash scripts/check.sh`: тесты, проверку
оформления Python, синтаксиса Bash и ShellCheck, если он установлен.
Проверки оформления контролируют длину строк, файлов и функций,
число аргументов, наличие docstring и оценку сложности функций.

| Проверяемый случай | Bash | Windows |
| --- | --- | --- |
| Без параметров | `scripts/run_no_args.sh` | `scripts/run_parameters.bat` |
| Только путь VFS | `scripts/run_with_vfs.sh` | `scripts/run_parameters.bat` |
| VFS и стартовый сценарий | `scripts/run_with_script.sh` | `scripts/run_parameters.bat` |
| Варианты VFS и ошибки загрузки | `scripts/run_vfs_variants.sh` | `scripts/run_vfs_variants.bat` |
| Все команды этапа 4 и ошибки | `scripts/run_stage4.sh` | `scripts/run_stage4.bat` |
| Все команды этапа 5 и ошибки | `scripts/run_stage5.sh` | `scripts/run_stage5.bat` |

В Bash запускайте сценарий через `bash`. Сценарии этапов содержат
намеренные ошибки команд для проверки продолжения выполнения.
Невозможность загрузить VFS возвращает код 1. Сценарий проверки VFS
ожидает этот код у ошибочных примеров и возвращает 0 при успехе проверки.

Автоматические тесты проверяют кавычки, обработку ошибок, параметры,
GUI, последовательное выполнение сценариев, JSON и base64, навигацию,
поиск, календарь, команды изменения и права доступа. Отдельная проверка
сравнивает исходный JSON до и после изменений и повторно загружает VFS.
Для GUI-тестов нужен Tkinter и доступный графический сеанс.
